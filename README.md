![ОренКод-2026 — чемпионат и первенство Оренбургской области по спортивному программированию](orencode-2026.png)
## Программирование БАС

Набор Python-скриптов для Геоскан Pioneer Mini: генерация калибровочной шахматной доски, калибровка камеры, определение положения по карте ArUco-маркеров, навигация к выбранному маркеру и отдельный модуль мягкой посадки.

Навигационный скрипт использует отдельные кадры, повторные попытки получения изображения, отбрасывание дубликатов и медианную оценку позы по нескольким кадрам.

| Файл | Назначение |
| --- | --- |
| `make_chessboard.py` | Создаёт PDF шахматной доски для калибровки камеры. По умолчанию — A4 в альбомной ориентации, 10 × 7 клеток по 25 мм и 9 × 6 внутренних углов. |
| `calibrate_camera.py` | Калибрует камеру по шахматной доске. Получает кадры с камеры Pioneer либо обрабатывает изображения из папки. Сохраняет `camera_calib.npz` и `camera_calib.yaml`. |
| `pioneer_aruco_nav.py` | Читает карту маркеров из TXT, определяет позицию камеры в системе координат карты, калибрует преобразование в локальные координаты Pioneer и перемещает дрон к выбранному ID. |
| `smart_land.py` | Отдельный модуль мягкой посадки по данным дальномера с управлением вертикальной скоростью. Может запускаться в демонстрационном режиме или вызываться из пользовательского кода. |
| `fsp.txt` | Соревновательная карта ArUco-маркеров. Используется по умолчанию; вместо него можно передать другой TXT-файл в поддерживаемом формате. |
| `chessboard_A4.pdf` | PDF, создаваемый `make_chessboard.py`. Если файл не приложен к репозиторию, сгенерируйте его командой из раздела «Калибровка камеры». |
| `camera_calib.npz` | Результат калибровки, необходимый навигационному скрипту для расчёта позы с нормальной точностью. Создаётся `calibrate_camera.py`. |

## Требования и установка

Для этого проекта рекомендуется **Python 3.12.x**. Документация GEOSCAN указывает поддержку Python 3.8–3.12, а PyPI для `pioneer-sdk` 0.6.1 — `>=3.8, <3.13`. Версию 3.12 удобно использовать как общую среду.

Используется пакет `pioneer-sdk`, который импортируется в коде как `pioneer_sdk`. В документации GEOSCAN `pioneer_sdk2` указан для модуля Pi Zero 2W; для работы с этим Pioneer Mini устанавливайте `pioneer-sdk`.

Зависимости проекта:

- `pioneer-sdk==0.6.1` — связь с дроном и получение кадров;
- `opencv-contrib-python` — обработка изображений, шахматная доска и ArUco;
- `numpy` — матричные вычисления;
- `Pillow` — генерация PDF-доски.

Создайте виртуальное окружение в каталоге проекта.

**Windows (PowerShell):**

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install pioneer-sdk==0.6.1 opencv-contrib-python numpy Pillow
```

**Linux:**

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install pioneer-sdk==0.6.1 opencv-contrib-python numpy Pillow
```

Проверка импорта:

```bash
python -c "from pioneer_sdk import Pioneer, Camera; import cv2, numpy; from PIL import Image; print('Imports OK; OpenCV:', cv2.__version__)"
```

Перед запуском на реальном аппарате подключите компьютер к Wi-Fi сети Pioneer Mini. Доступ к интернету при этом может отсутствовать, поэтому установите зависимости заранее. Подключение и настройку самого аппарата выполняйте по инструкции GEOSCAN для используемой версии оборудования и прошивки.

## Калибровка камеры

Калибровка нужна для корректного восстановления положения камеры из изображения. Можно использовать готовый `camera_calib.npz`, если он предоставлен для той же модели камеры, либо один раз выполнить собственную калибровку. Файл от другой камеры той же модели может подойти, но индивидуальная калибровка обычно точнее.

### 1. Создание шахматной доски

```bash
python make_chessboard.py --square 25 --out chessboard_A4.pdf
```

По умолчанию генерируется доска с 9 × 6 внутренними углами, 10 × 7 клетками и размером клетки 25 мм. Распечатайте PDF **в масштабе 100%**, без подгонки под страницу. Измерьте фактическую сторону клетки линейкой и передайте измеренное значение в параметр `--square`. Закрепите лист на плоской жёсткой основе, чтобы доска не изгибалась.

### 2. Съёмка кадров и расчёт параметров

Для калибровки по камере Pioneer Mini включите автоматический сбор кадров:

```bash
python calibrate_camera.py --square 25 --auto
```

Вместо `25` укажите фактически измеренный размер клетки в миллиметрах. Медленно перемещайте доску относительно камеры: в центре и по краям изображения, ближе и дальше, с разными наклонами. Нужны не менее 8 кадров, желательно 20 или больше. Индикаторы в окне показывают покрытие положений доски по координатам X/Y, размеру и наклону.

Управление в окне:

- `SPACE` или `s` — сохранить кадр, если доска обнаружена;
- `a` — включить или выключить автоматический сбор кадров;
- `c` — выполнить калибровку и сохранить результат;
- `u` — показать или скрыть исправленное от дисторсии изображение;
- `ESC` или `q` — выйти.

Результат сохраняется в `camera_calib.npz` и `camera_calib.yaml`. По умолчанию сохранённые кадры размещаются в `calib_images/`.

Если кадры уже собраны, калибровку можно выполнить офлайн:

```bash
python calibrate_camera.py --images calib_images --square 25
```

Для широкоугольного объектива можно сравнить обычную модель с моделью, включающей дополнительные коэффициенты дисторсии:

```bash
python calibrate_camera.py --square 25 --rational
```

### Контрольный результат

Для использованной при подготовке проекта камеры автор получил по 80 кадрам RMS-ошибку репроекции около **0,35 px**. Параметры соответствовали кадру **480 × 320 px**: `fx ≈ 474,9`, `fy ≈ 474,3`, главная точка `(272, 183)`, оценка угла обзора около **54° × 37°**; коэффициенты дисторсии `k1 ≈ 0,12`, `k2 ≈ -0,14`. Это ориентир для проверки собственного результата, а не замена файла `camera_calib.npz`.

Навигационный скрипт умеет масштабировать матрицу камеры, если фактическое разрешение кадра отличается от разрешения калибровки, но наилучшую точность следует ожидать при том же разрешении. Если `camera_calib.npz` отсутствует, `pioneer_aruco_nav.py` использует упрощённую модель с запасным горизонтальным углом обзора 80° и нулевой дисторсией. Для навигации по карте такой запасной вариант заметно менее точен; перед полётом используйте файл калибровки.

## Навигация по карте ArUco

### Формат карты

`pioneer_aruco_nav.py` принимает TXT-карту в формате Clover. Каждая строка содержит:

```text
id length x y z rot_z rot_y rot_x
```

- `id` — идентификатор маркера;
- `length` — длина стороны маркера в метрах;
- `x`, `y`, `z` — координаты центра маркера в метрах;
- `rot_z`, `rot_y`, `rot_x` — углы поворота вокруг соответствующих осей в радианах.

Допускаются пробелы, табуляция, запятые и точки с запятой в качестве разделителей. Пустые строки и комментарии после `#` игнорируются. Если заданы только первые пять значений, углы считаются нулевыми.

Пример:

```text
0 0.2 0.0 7.2 0.0 0 0 0
```

Можно загрузить любую карту в этом формате, не меняя код:

```bash
python pioneer_aruco_nav.py --map my_map.txt --calib camera_calib.npz
```

Для `fsp.txt` в текущем наборе данных определяются 171 маркер. При использовании другой карты проверьте, что координаты, размеры, ID и углы поворота соответствуют реальному полю.

### Словарь маркеров

В коде по умолчанию указан `DICT_4X4_250`. Это предположение, которое необходимо проверить для фактически напечатанных маркеров. Подключите дрон к компьютеру, поднесите камеру к полю и выполните:

```bash
python pioneer_aruco_nav.py --find-dict
```

Скрипт анализирует один полученный кадр и выводит словари, в которых найдено больше маркеров. Выбирайте словарь, где находятся ожидаемые ID из карты, и задайте его через `--dict`.

### Проверка позы без полёта

Сначала проверьте оценку координат с дроном на поле, не запуская навигацию:

```bash
python pioneer_aruco_nav.py --map fsp.txt --calib camera_calib.npz --pose-only
```

Перемещая дрон вручную над полем, проверьте, что значения `x` и `y` меняются в соответствии с положением на карте. Этот режим использует камеру и не должен выполнять взлёт.

Для проверки одиночной фотографии без подключения к Pioneer:

```bash
python pioneer_aruco_nav.py --map fsp.txt --calib camera_calib.npz --image photo.png
```

При необходимости `--debug-dir debug_frames` сохраняет кадры с разметкой и рассчитанной позой.

### Как устроена навигация

Камера должна смотреть вниз на поле. По углам всех распознанных известных маркеров алгоритм `solvePnP` оценивает положение камеры в системе координат TXT-карты. Для оценки кадра требуются как минимум два маркера из карты; результат отбрасывается, если ошибка репроекции слишком велика.

При первом запуске навигации скрипт автоматически определяет соответствие осей карты и локальных осей Pioneer. Для этого он измеряет исходное положение, перемещается на **0,4 м по local X**, возвращается к исходной точке, затем выполняет аналогичную пробу по **local Y**. По двум смещениям рассчитывается преобразование между системами координат. Поэтому дрону нужно пространство для двух коротких пробных перемещений, а карта должна оставаться видимой во время калибровки.

В текущей версии `pioneer_aruco_nav.py` эта калибровка осей запускается автоматически при каждом штатном старте навигации. После каждого перемещения скрипт получает новую оценку позы по камере и рассчитывает остаточную ошибку к центру целевого маркера. Это уменьшает накопление ошибки от дрейфа локальной позиции. По умолчанию используется допуск **8 см**, не более **6 коррекций** на цель и максимальный шаг **1 м** на одну команду.

Задержки Wi-Fi учитываются следующим образом: пустые кадры и дубликаты отбрасываются, после перемещения накопившиеся старые кадры сбрасываются, а поза рассчитывается как медиана по окну из нескольких кадров. На получение достоверной позы отводится ограниченное время. Если карта потеряна несколько раз подряд, навигация к текущей цели прекращается, чтобы не продолжать движение по неактуальной оценке.

### Запуск

Перед полётом убедитесь, что:

- установлен правильный словарь ArUco;
- карта соответствует расположению маркеров, а размеры заданы в метрах;
- камера направлена вниз и `camera_calib.npz` соответствует камере;
- на стартовой позиции камера видит не менее двух маркеров из карты;
- вокруг достаточно места для взлёта, пробных смещений и манёвров.

Пример запуска:

```bash
python pioneer_aruco_nav.py --map fsp.txt --calib camera_calib.npz --dict DICT_4X4_250 --height 1.0
```

Для первого испытания выберите низкую рабочую высоту и маркер рядом с начальной точкой. Параметр `--height` задаёт рабочую высоту в метрах; по умолчанию в коде установлено 1,5 м.

В интерактивном цикле:

- `ID` — лететь к центру маркера с указанным ID;
- `p` — вывести текущую позу по карте;
- `c` — повторить калибровку осей;
- `l` или `q` — завершить цикл навигации и перейти к посадке.

Другие параметры:

```bash
python pioneer_aruco_nav.py --debug-dir debug_frames
python pioneer_aruco_nav.py --simulator
python pioneer_aruco_nav.py --help
```

`--simulator` включает режим симулятора Pioneer SDK. `--debug-dir` задаёт папку для сохранения диагностических кадров. Режим `--image` предназначен для отдельной картинки; `--find-dict` — для подбора словаря по кадру с камеры или по картинке; `--pose-only` — для наблюдения за положением без запуска полёта.

По умолчанию модель маркера в карте предполагает, что маркеры лежат лицевой стороной вверх: верхняя сторона маркера направлена вдоль **+Y карты**, правая — вдоль **+X карты**. Если фактическая ориентация отличается, проверьте параметры `rot_z`, `rot_y`, `rot_x` и результат оценки позы. Если камера установлена не по центру дрона, скорректируйте `CAMERA_OFFSET_CAM` в начале `pioneer_aruco_nav.py`.

## Мягкая посадка

`smart_land.py` предназначен для снижения на поверхность, в том числе на приподнятую площадку, когда требуется управлять вертикальной скоростью по данным дальномера, а не только задавать целевую координату высоты.

Для отдельного демонстрационного запуска со взлётом, зависанием и посадкой:

```bash
python smart_land.py --demo --height 1.0
```

Для тестирования в симуляторе:

```bash
python smart_land.py --demo --height 1.0 --simulator
```

Если объект `Pioneer` уже создан и дрон находится в воздухе, функция вызывается из пользовательского кода:

```python
from smart_land import smart_land

smart_land(drone)
```

Перед снижением функция ждёт стабилизации, определяет знак вертикальной скорости, фильтрует резкие скачки показаний дальномера и плавно снижает скорость с 0,3 до 0,1 м/с по мере приближения к поверхности. Порог штатного выключения моторов по умолчанию — **0,12 м** над поверхностью. Значения скорости, высоты и временных ограничений можно изменить в начале `smart_land.py`; параметры нужно подбирать и проверять для конкретного аппарата и поверхности.

Если данных дальномера нет, модуль переходит к обычному `drone.land()`. При потере данных у поверхности он может выполнить `disarm()`, а при общем таймауте — вызвать штатную посадку. Это не универсальная гарантия мягкого касания: проверьте высоту срабатывания, качество данных дальномера и поведение дрона на безопасной площадке. В демонстрационном режиме `Ctrl+C` приводит к вызову `disarm()`, а не к обычной посадке; не используйте это прерывание как стандартную команду посадки.

**Интеграция с навигацией:** в приложенной версии `pioneer_aruco_nav.py` команда `l` и завершение скрипта вызывают стандартный `drone.land()`. `smart_land.py` — самостоятельный модуль и автоматически не вызывается навигатором. Для мягкой посадки из навигационного сценария вызов `smart_land(drone)` необходимо явно интегрировать в код и проверить отдельно.

Проверки, выполненные при подготовке проекта, были синтетическими; на реальном Pioneer Mini скрипты не запускались. По тестам автора, `fsp.txt` успешно разбирается, положение по смоделированному кадру восстанавливалось с погрешностью порядка 1 мм по X/Y, а процедура калибровки осей проходила до конца на смоделированных данных. Эти результаты проверяют математическую часть, но не подтверждают работу Wi-Fi, SDK, камеры, локальной позиции или посадки на реальном аппарате.
